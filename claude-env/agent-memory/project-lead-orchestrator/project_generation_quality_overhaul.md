Generation-quality overhaul batch (docs/intake/generation-quality-overhaul-2026-07/, 6 briefs P1–P5+V1). SHIPPED v1.13.0 (2026-07-01, DB unchanged v16). One coordinated stream — all six edit AiRepository.kt (~2040 lines); do NOT fan out.

**Why:** headline complaint "exercises or weights are off" = the generator force-churned main lifts every week (blacklist "single most important constraint" + "rotate every week" + mandatory variation theme) and guessed weights on the forced-new lifts.

**Load-bearing facts (non-obvious):**
- **Per-rep work constant is now 4 s (was 3 s)** — `WorkoutTimeEstimator.WORK_SECONDS_PER_REP`. It MUST stay in lockstep with the prompt TIME-BUDGET formula text in TWO places in AiRepository (weekly `buildPrompt` + single-day `buildSingleDayPrompt`). Changing it shifts every Program-screen "~Xm" display AND the ±10 gate. It rippled into 5 test files that hand-compute minutes (WorkoutTimeEstimator/H3/G1/G2/R1) — recompute if you touch it again.
- **The hypertrophy "hammer" was DELETED**: `hypertrophyRestDirective` (forced 120 s rest + ~19–20 sets → ~46 min) is GONE, and `dayDurationFeedback` lost its `hypertrophy: Boolean` param → now goal-general + duration-derived. The old fixed 46-min/20-set/120s constants are what bounded sessions at ~45–50 min. Do NOT reintroduce them — sizing is now derived from goal×experience×days×duration for the full 20–120 min range.
- **The 120 s hypertrophy rest ceiling is removed everywhere**: prompt (§5 wide bands: strength rest ≤300s, hypertrophy compounds ≤240s) AND `validateProgram` item #4 (was "reject if rest >120s"). The `parseProgram` rest clamp was raised 180→600 (loose sanity ceiling only). Wide §5 rep/rest bands replaced the narrow role→rep table.
- **P1 middle-ground**: keep+progress most main lifts; ≤2 FULL main-lift swaps/week; vary grip/angle/accessories/order/weekday freely; weights anchored to logged history or a closely-related logged lift (never fabricated). The old blacklist block is now "RECENTLY USED — VARY, don't churn".
- **V1 ladder ALREADY EXISTED** in code (generate→validate→regenerate cap 3→trimOverflowToWindow deterministic fix→re-validateProgram→save-or-throw + 360s deadline). V1's actual work was making `validateProgram` NOT false-reject: added a SOFT-BAND GUARD (never hard-reject on §5 numeric ranges), coverage-scaling for movement balance, and P4-aligned injury (MILD not required to change selection/add rehab; empty injury = no injury-driven rejection). Do NOT add new subjective HARD rejects — that reopens the v1.10.7 false-reject wound.
- **P5 metadata**: full §6 declared metadata added to the OUTPUT contract + parse model (ExJson/DayJson gained fields, new WeekMetaJson; all defaulted so old/lean responses still parse — Gson ignores unknowns). WorkoutTimeEstimator stays AUTHORITATIVE for the gate — declared minutes are audit-only, never trusted to pass the gate (would let the model game it). sonnet-4-6 max output 64K ≫ maxTokens 16384 ≫ ~4–6K expected output, so token-cap truncation is impossible; only generation latency grows (bounded by streaming + 360s deadline).
