**Why / load-bearing design choices (not obvious from a later diff):**
- **Single-day regen parity (P4)** = `AiRepository.generateSingleDayProgram` rewritten into the SAME loop as the weekly path (retry≤3 + strict `dayDurationFeedback` gate + trim-salvage + `validateProgram`). The all-BW bug was the prompt sending NO history + a hard-coded `targetWeightKg:0` example; the same-workout bug was no history/variation + excluding the current day. Fix = history block + non-zero example + variation theme + blacklist of the day's current/recent exercises. **Peer review runs in FULL-WEEK context** (`otherDays + newDay`, `daysPerWeek = resulting distinct day count`) so the weekly checks (recovery/balance/day-count) are meaningful — a 1-day-program edge could over-reject.
- **Shared rebalance seam:** `ProgramViewModel.runRebalance(extraLockedDays,…)` now underpins B09 regen (`extraLockedDays=∅`), **P1** (`={changedDay}`), and **P2** (`=∅`, today already logged). It locks loggedDays+extra, generates around them, saves via `savePlanPreservingLoggedDays` (logged days/sets never touched).
- **P1 focus-change trigger** = `domain/MuscleFocus.changed(before,after)` (dominant muscle group; tie→alphabetically-last, deterministic). Wired into `regenerateDay` + the structural manual edits (add/delete/swap); field edits + reorder never trigger. Toggle = `prefs.autoRebalanceEnabled` (default OFF), surfaced in the Program **options dialog**. Residual: a manual edit during an in-flight rebalance isn't blocked (edit buttons stay live).
- **P2 move-on-completion:** entry = `btn_do_today` on an eligible OTHER day (not today, not logged, today not logged — [P2-A4]). Threaded as `moveFromDay` Bundle arg → LogWorkoutVM performs the SOURCE day's plan but attributes to today. **Commit ONLY in `completeWorkout`** via `WorkoutRepository.commitDayMove` + pure `domain/DayMovePlanner.movedRows` (source→today logged, today's original discarded, source cleared). Abandon clears `moveFromDay` ⇒ week untouched. Rebalance fires from `ProgramFragment.onResume` via `SharedWorkoutResultViewModel.moveRebalancePending` (so it runs ON the Program tab with the animation, surviving the log→program nav) and ALWAYS runs regardless of the P1 toggle.
- **P3 notifier** = `notify/GenerationNotifier` injected into `AiRepository`, hooked at BOTH program-gen methods via `.also { notifyProgramGenerationComplete(it.isSuccess) }` — one seam covers every entry point (auto-gen/Settings/wizard/single-day/P1/P2 rebalances), success AND terminal-failure. Backgrounded-only via `notify/AppForegroundState` (ActivityLifecycleCallbacks in TreningsprogramApp). Tap → Program tab (MainActivity `singleTop` + `onNewIntent` + `EXTRA_OPEN_PROGRAM`). Permission-denied ⇒ silent no-op. Does NOT cover weekly-summary/onboarding (not program gen).
- **P5** = `ui/common/GenerationTips` rotated every 4.5 s via `collectLatest` on the generating flow into a SEPARATE tip TextView under the real status line, on all 3 wait layouts (program/settings_ai/setup_wizard).
