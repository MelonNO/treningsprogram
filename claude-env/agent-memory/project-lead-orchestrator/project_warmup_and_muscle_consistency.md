Two cross-cutting invariants in [[project-treningsprogram]] that are easy to break and were both violated until the 2026-06-23 QA pass (fixes on branch `qa-pass-fixes`, working-tree only — NOT committed/released).

**Invariant 1 — "working set" = `isWarmup == 0` everywhere.** The whole app treats stats/PRs/volume/recap as non-warmup only (e.g. `getWorkingSetCount`, `buildSessionRecap` filter `!it.isWarmup`, PR detection). But four aggregate DAO queries (`getTotalSets`, `getTotalVolumeKg`, `getMuscleGroupVolume`, `getRepRangeDistribution`) and `getStrengthHistory` had NO `isWarmup` filter, so the Stats tab + Profile tiles + strength chart silently counted warm-ups. **Why it matters:** any NEW aggregate query over `workout_sets` must add `WHERE isWarmup = 0` unless it deliberately wants warm-ups. **How to apply:** when adding a stats query, mirror the existing working-set filter.

**Invariant 2 — muscle group is resolved at set-WRITE time, with a name-based fallback.** `WorkoutSet.muscleGroup` is denormalized and `PlannedExercise` has NO muscle field. Sets used to resolve muscle ONLY via `AppDatabase.DEFAULT_EXERCISES` exact-name match → swapped calisthenics progression variants (e.g. "Archer Push-Up", "Pistol Squat" — these are CalisthenicsProgressionMap targets, NOT in the 36 DEFAULT_EXERCISES) and custom "Add anyway" exercises stored `muscleGroup = ""` and were dropped by `WHERE muscleGroup != ''`. Fix added `data/MuscleClassifier.kt` (shared name→canonical-group keyword classifier, Legs-before-Back ordering, returns "" when unknown) used by `LogWorkoutViewModel.resolveMuscleGroup()` in all set-write paths. **How to apply:** any code path that creates a `WorkoutSet` must set a real muscleGroup; reuse `MuscleClassifier.fromName()` as the fallback.

**R1 recognition fix (DONE 2026-06-26, branch `exercise-recognition-fix-2026-06`, verified, NOT yet shipped — likely v1.10.2):** `MuscleClassifier.fromName` was made PATTERN-LEVEL (not just literal names). New ordering (precedence matters): balance/mobility ("balance hold"/"ankle alphabet"/"foot circles") → "" first; genuine cardio (NO tempo/interval); rear-delt/reverse-fly/face-pull/y-raise → Shoulders BEFORE Chest; any "row" → Back BEFORE Chest (so a chest-supported row is Back, a rear-delt row stays Shoulders); Chest; Legs (+`tibialis`, before remaining Back for romanian/RDL); Back; Shoulders (+`arnold`); Arms; Core; `walk` → Cardio LAST (so "walking lunge"/"walking plank" classify by their strength move). `finerMusclesFor` got 3 surgical edits to stay consistent (tempo/interval removed; posterior-shoulder rules moved above the chest/pressing block; `&& !contains("row")` guard on the two "bench"/"incline bench" chest rules). **NEW: write-time resolution is now `data/MuscleGroupResolver.resolve(name)` (= DEFAULT_EXERCISES exact match → `fromName` fallback) — the SAME object is reused by the historical backfill so a re-derived old set carries exactly what a new set would. Backfill = data-only Room `MIGRATION_14_15` (DB 14→15) that re-derives ONLY the `muscleGroup` column per distinct exerciseName, parameterized + idempotent, no schema change. Fixture/guards in `docs/intake/exercise-recognition-fix-2026-06/`; guarded by `R1ExerciseRecognitionTest` + `R1BackfillMigrationTest`.** How to apply: keep using `MuscleGroupResolver.resolve()` for any new WorkoutSet write path; if you correct the classifier again, a parallel backfill migration is the established pattern.

**F3 follow-up (DONE, batch 2):** `MuscleClassifier` is now the ONE classifier. `ProgramFragment.getMuscleGroup/getMuscleStyle` and `LogWorkoutFragment.getMuscleGroupName/getMuscleStyle` were collapsed to delegate to `MuscleClassifier.displayName()` (group, or "Training" for badges) + `MuscleClassifier.colorFor(group, fallbackColor)` (canonical 7 colors; each screen keeps its own neutral fallback — Program `#607D8B`, Log `#7C67F5`). The old per-screen keyword lists are GONE. Badge labels now equal the stored muscle group (e.g. "Romanian Deadlift" → Legs on BOTH screens; Log previously said Back). Verified on-device. Don't reintroduce a per-screen keyword classifier.

**G2 (DONE, batch 2):** the auto-generate "which week did I last generate" marker is now `autoGenWeekKey()` (file-scope in `WorkoutRepository.kt`, = `"wk-${thisMonday()}"`), locale-INDEPENDENT. Replaced `SimpleDateFormat("yyyy-'W'ww", Locale.getDefault())` at all 4 auto-gen sites: `MainActivity` (reader+writer), `SettingsViewModel`, `SetupWizardViewModel`. NOTE: `DailyChallengeManager.WEEK_FMT` still uses `yyyy-'W'ww` for a SEPARATE key (weekly-challenge rotation, `dailyChallengesJson.date`) — deliberately left untouched (out of scope; changing it shifts challenge resets for existing users), but it has the same latent locale bug if ever touched.

**Verified-NOT-a-bug:** `getStrengthHistory`'s bare `ws.reps` alongside `MAX(ws.weightKg) GROUP BY sessionId` is NOT non-deterministic — SQLite's documented single-min/max bare-column rule returns reps from the max-weight row. Two diagnostic sub-agents flagged it as a bug; both were wrong. Don't re-flag it.
