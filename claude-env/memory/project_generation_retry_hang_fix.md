User report: tapping **Program → Generate AI Program** on v1.10.2 froze on "Generating 2 of 3" forever and produced no plan ("the verify prompt / verification prompt" never recorded). The user supplied the actual generation prompt + a complete valid model JSON + a screenshot of the in-app **Prompt Log** (Profile tab; records each AI call as e.g. "GENERATE ATTEMPT 1") showing only one entry. "verification prompt" = the **validateProgram** second Claude call (prompt opens "You are a sports science peer reviewer," UI status "Reviewing plan for quality…").

**Diagnosed root cause (not an infinite hang):** attempt 1's plan was rejected by the strict per-day time-budget gate (days estimated 38/34/34/39/37 min, all under the 40 floor) → verify correctly skipped → loop advanced to attempt 2 ("ADD work") → bigger/slower non-streaming response blew the 180s read timeout → `withAiRetry` re-fired the same oversized request with **no backoff** → ~8 min burned; the eventual error was a one-shot Snackbar the user never saw (was on the Prompt Log screen). So "forever" = ~8 min of invisible failure. Same time-budget seam as [[project_generation_timebudget_fix]] (v1.10.1) — whose steering proved insufficient.

**Scope (user-confirmed):** BOTH "never hang" AND "actually get a plan." Full pipeline (intake-understanding → project-lead-orchestrator → build-release-shipper); on-device/Waydroid skipped per [[feedback_always_skip_waydroid]]; verified by build + unit tests only.

**Fixes (all in `data/repository/AiRepository.kt`, +158/−23; gate/caps/NetworkModule/maxTokens UNTOUCHED):**
- **H1 (hang):** generation calls that hit a timeout are no longer retried (`isTransientGenerationError` excludes `SocketTimeoutException`; `withAiRetry` gained an `isRetryable` predicate so validate/onboarding/weekly/single-day are unchanged); whole flow wrapped in `withGenerationDeadline` = `withTimeout(360_000ms)` → narrow catch of `TimeoutCancellationException` → terminal `IllegalStateException("Generation took too long…")` via existing failure path. Ends in ~180s with a clear error instead of ~8 min.
- **H3 (under-fill, prompt-side ONLY, gate stays strict):** prompt now names "**REST IS YOUR #1 TIME LEVER**" + an ordered UNDER-FILL CORRECTION (raise rest→reps→add set→add accessory, all within the ≤18–20-set / ≤7-exercise caps) + forced silent per-day arithmetic. **No structural-tension wall:** raising rest to the allowed 120s moves the captured plan 38/34/34/39/37 → 46/42/39/49/47 with ZERO added volume. Reject conditions byte-for-byte unchanged.
- **H2 (secondary):** blacklist was rebuilt by `split(",")` on the rendered plan string → shattered comma-containing names (`"…(Seated, Alternating)"` → junk) + harvested the `"Mon: …"` header line. Now built from structured `PlannedExercise.exerciseName` set (`buildBlacklistNames`).
