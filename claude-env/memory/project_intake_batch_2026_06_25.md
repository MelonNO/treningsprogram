## The 10 items (confirmed scope)
1. **Enlarge in-session progress-bar hit box** (active workout screen "Exercise X/Y" bar opens the quick-jump menu; tap target too small). Bug/usability.
2. **New bodyweight exercise must default to 0/"BW"**, not inherit the previous exercise's weight. If that exercise was previously logged WITH added weight, still prefill ITS OWN last weight — only the cross-exercise bleed is the bug. Logging bug.
3. **Progress-tab exercise picker sorted by most sessions** (descending; ties→alphabetical; typing-filter keeps the order). Improvement.
4. **Achievements list defaults to COLLAPSED** on Profile (flip current default; always start collapsed). Improvement.
5. **Clean up downloaded update APKs** — cleanup on app launch (Android can't signal exact install-finish), AND only after verifying the update actually completed (don't delete unless install succeeded / installed version is the new one). Housekeeping.
6. **Tap recovering muscle → highlight the exercise(s) that caused it**: still opens the last session that trained it, but now scrolls to + highlights ALL exercises that hit that muscle; highlight lives IN the session view (no culprit name on the Home row). Builds on v1.9.0 recovery rework.
7. **Hide empty data fields** app-wide (Recap/Progress/History/Stats/Trends) instead of "log more to see X" copy — hide the chart/section until data. KEEP one short top-level line on an otherwise-completely-empty screen (e.g. "Complete a workout to see your stats") to avoid a blank-looks-broken screen. Improvement.
8. **Choose specific rest day(s) when generating** — TWO MODES via a "you choose days" checkbox: DEFAULT (off) = user picks the specific rest days, days/week DERIVED from it; ALT (on, "you choose days") = old behavior, user picks the NUMBER of days, AI chooses which. Configurable in BOTH setup and Settings. AI-generation seam.
9. **Mid-week regenerate preserves logged days** (AI-generation seam, HIGHEST RISK): any day with **≥1 logged exercise = preserved**; every day WITHOUT a logged exercise is regenerated — PER-DAY, not a time boundary (e.g. only Wed logged → regenerate all days except Wed, incl. days before today). AI **rebalances/overwrites the still-unlogged planned days** around the logged work (muscle groups/volume/recovery), not just filling blanks. The existing **Program-tab "regenerate" button BECOMES this** behavior. **Full-fresh-week** (regenerate ALL incl. logged) moves **behind Settings**; overwrites only PLANNED exercises, NEVER deletes logged sets/history/any user data. Current Mon→Sun week; preserves THIS week's logged day. No change to auto start-of-week generation.
10. **AI emits reasoning/prose instead of JSON → stalls** (AI-generation seam; same class as v1.9.0 S3 finding). ROOT CAUSE found by understander: no-JSON `extractJsonOrThrow` THROWS outside the retry path → aborts whole generation instead of counting as a rejected attempt; max_tokens 8192, no verbosity control, prompt invites planning → model burns budget on prose, truncates before JSON. FIX = RECOVER (treat no-JSON AND truncated responses as rejected attempts → retry up to limit → clear error if all fail, never silent stall) + PREVENT (ensure JSON reliably emitted+extracted). **KEY STEER: do NOT strip reasoning — reasoning-then-JSON is fine as long as the app can extract the JSON. PRIORITY ORDER: (1) HIGH-QUALITY plan, (2) fewer rejects, (3) ideally never fails. Quality OUTRANKS reject-rate.**
